# 架构说明

## 一、角色划分

| 角色 | 定位 | 状态 | 说明 |
|---|---|---|---|
| 主控 Leader | 编排者 | 有会话 | 接收请求、解析输入、按序调用子智能体、汇总结果 |
| 预处理 Preprocess | 能力提供者 | 无状态 | 解码、裁剪、缩放，返回处理后图像与元数据 |
| 检测 Detect | 能力提供者 | 无状态 | 模型推理，返回缺陷列表 |
| 报告 Report | 能力提供者 | 无状态 | 依据检测结果生成报告与判定 |
| 回流 Feedback | 能力提供者 | 有持久化 | 保存样本、维护统计、触发重训请求 |

## 二、一次调用的完整时序

```
调用方            主控            预处理         检测          报告
  │                │                │             │             │
  │ start(image)   │                │             │             │
  ├───────────────►│                │             │             │
  │                │ start(image)   │             │             │
  │                ├───────────────►│             │             │
  │                │◄───────────────┤ 处理后图像   │             │
  │                │ start(image)   │             │             │
  │                ├─────────────────────────────►│             │
  │                │◄─────────────────────────────┤ detections  │
  │                │ start(detections)            │             │
  │                ├──────────────────────────────────────────►│
  │                │◄──────────────────────────────────────────┤ report
  │◄───────────────┤ 汇总：检测+报告              │             │
  │ complete       │                │             │             │
  ├───────────────►│                │             │             │
```

## 三、关键设计取舍

### 1. 主控编排而非网状调用

子智能体之间不互相调用，所有编排集中在主控。

- 优点：依赖关系清晰，单点可观测，便于审计与排障
- 代价：主控成为单点，需要额外保障可用性

### 2. 本地优先的伙伴解析

平台发现服务返回的是公网端点。若服务与调用方在同一台机器上，经由公网回环会产生额外延迟并增加断连概率。

因此解析到伙伴端点后，会把已知的公网端口重写为本地端口，保持协议与证书校验不变：

```
https://host:8443/rpc  →  https://127.0.0.1:8013/rpc
```

### 3. 双形态输出

检测结果同时以结构化对象与纯文本 JSON 返回。

原因：部分调度器只读取文本类数据项，结构化对象会被忽略，导致上一步结果无法传给下一步。

### 4. 宽容入参

每个智能体接受的图像入参形式：

1. FileDataItem，bytes 为 base64
2. TextDataItem，内容为 base64、data URI 或本地绝对路径
3. TextDataItem，内容为 http/https 链接
4. 说明文字中内嵌上述任意一种

判定顺序：先识别链接，再尝试 base64，最后按本地路径处理。

顺序不可颠倒：URL 字符串能被 base64 解码成无意义字节，若先尝试 base64 会得到损坏图像。

## 四、日志体系

| 类型 | 触发 | 关键字段 |
|---|---|---|
| access | 每次对外调用 | caller AIC、callee AIC、method、statusCode、durationMs、correlationId |
| message | 消息生命周期 | eventType、messageId、destination、payloadSizeBytes |
| heartbeat | 每 15 秒 | aic、uptimeSeconds |

message 的 eventType 取值受规范约束：send / receive / ack / nack / reject / timeout / dead_letter。
不存在 complete 这一取值，任务完成以 ack 表达。
